NEW FILES CREATED:
------------------

1. audiosystem.h
   - Centralized audio input system with FFT1024 analysis
   - Provides shared audio data to all color functions
   - Key features: frequency band analysis, peak detection, caching
   - Main interface for all audio-reactive effects

2. audiosystem.cpp
   - Implementation of AudioSystem static members
   - Audio component definitions and connections
   - State variable initialization

3. AUDIO_SYSTEM_README.md
   - Complete documentation of the audio system
   - Usage examples and migration guide
   - Troubleshooting information
   - API reference

4. AUDIO_REACTIVE_EXAMPLES.h
   - 5 example custom audio-reactive color functions:
     * FrequencyBandVisualizer - Different bands in different zones
     * BassPulseFunction - Pulses with bass frequencies
     * SpectrumAnalyzer - Classic spectrum analyzer display
     * BeatDetector - Detects beats and creates flashes
     * VocalHighlighter - Responds to vocal frequencies
   - Complete usage instructions

---------------

   - Added #include "audiosystem.h"
   - Updated AudioReactiveColorFunction to use AudioSystem::getLevel()
   - Updated VUMeterColorFunction to use AudioSystem::getLevel()

2. hdlo_controller.ino
   - Added #include "audiosystem.h"

   - Added AudioSystem::update() in loop()

   - Updated initialization order

KEY CHANGES:
------------

Before:
- Each audio function did its own analogRead()
- Multiple separate audio readings per frame
- No frequency analysis
- Noisy, inconsistent data

After:
- Single AudioSystem with FFT analysis
- One FFT update per frame, shared by all
- 40 frequency bands available
- Clean, consistent, efficient data

BENEFITS:
---------

1. Efficiency: Single FFT calculation instead of multiple analogRead() calls
2. Quality: Hardware FFT with proper frequency analysis
3. Consistency: All functions see the same audio data
4. Extensibility: Easy to add new audio-reactive effects
5. Maintainability: Single point of configuration

INTEGRATION:
------------

Required changes to existing code:
1. Add #include "audiosystem.h" to main sketch
2. Call AudioSystem::initialize() in setup (before color functions)
3. Call AudioSystem::update() at start of loop
4. That's it! All existing audio functions automatically use new system

NO BREAKING CHANGES:
- All existing APIs remain the same
- Audio pin parameters kept for compatibility
- Existing color functions work unchanged

AUDIO HARDWARE:
---------------

Requires:
- Teensy Audio Shield (or compatible)
- I2C connections (pins 18/19 on Teensy 4.x)
- Microphone or line input

Configuration:
- Input: AUDIO_INPUT_MIC (default)
- FFT Size: 1024 points
- Update Rate: 20ms (50 Hz)
- Memory: 12 blocks

TESTING COMMANDS:
-----------------

Serial monitor commands for testing:
- "audio" - Display current audio levels
- "gain 0.5" - Set microphone gain (0.0 to 1.0)
- "palettes" - List available color palettes
- "help" - Show all commands

FREQUENCY BANDS:
----------------

The system provides 40 frequency bands:
- Bands 0-9: Bass (20-200 Hz)
- Bands 10-19: Low-mid (200-1000 Hz)  
- Bands 20-29: Mid (1-3 kHz)
- Bands 30-39: High (3-10 kHz)

Helper methods:
- AudioSystem::getBass() - Average of bands 0-9
- AudioSystem::getMid() - Average of bands 10-19
- AudioSystem::getTreble() - Average of bands 20-29
- AudioSystem::getHighTreble() - Average of bands 30-39
- AudioSystem::getBand(n) - Individual band 0-39
- AudioSystem::getBandRange(start, end) - Custom range

PERFORMANCE:
------------

CPU Usage:
- FFT1024: ~5-10% CPU on Teensy 4.x
- Shared across all functions
- Update limited to 20ms intervals
- Cached results prevent redundant calculations

Memory Usage:
- Audio memory: 12 blocks (6KB)
- Cached bands: 40 floats (160 bytes)
- State variables: ~20 bytes
- Total: ~6.2 KB
