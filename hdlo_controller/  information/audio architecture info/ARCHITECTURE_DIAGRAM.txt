================================================================================
                         DATA FLOW TIMELINE
================================================================================

Each Frame (every ~16ms for 60 FPS):
────────────────────────────────────────────────────────────────────────

1. AudioSystem::update()
   │
   ├─► Check if 20ms elapsed since last update
   │   (Rate limiting - prevents excessive CPU usage)
   │
   ├─► IF time elapsed:
   │   │
   │   ├─► Read FFT data from AudioAnalyzeFFT1024
   │   │   (512 frequency bins available)
   │   │
   │   ├─► Sample 40 bands across spectrum
   │   │   • Bands 0-19: 5 bins per band (bass/low-mid detail)
   │   │   • Bands 20-39: 10 bins per band (mid/high)
   │   │
   │   ├─► Cache band values in array
   │   │
   │   ├─► Calculate overall level (average)
   │   │
   │   └─► Update peak level with hold time
   │
   └─► ELSE: Use cached values (no redundant FFT reads)

2. StatefulColorFunction::beginFrame()
   │
   └─► Increment global frame counter

3. For each audio-reactive color function THAT IS USED:
   │
   ├─► Check if already updated this frame
   │   (Lazy evaluation - only update if used)
   │
   ├─► IF not updated:
   │   │
   │   ├─► Call AudioSystem::getLevel() or getBass(), etc.
   │   │   (Uses cached data - instant access)
   │   │
   │   ├─► Update function's internal state
   │   │
   │   └─► Mark as updated for this frame
   │
   └─► Return color based on current state

4. Apply colors to LED array

5. FastLED.show()

================================================================================
                        FREQUENCY BAND MAPPING
================================================================================

  Band      Frequency Range        Musical Content
  ────      ───────────────        ───────────────
  0-4       20-100 Hz              Sub-bass, kick drum
  5-9       100-200 Hz             Bass guitar, bass drum
  10-14     200-500 Hz             Low-mid, male vocals
  15-19     500-1000 Hz            Mid, female vocals
  20-24     1-2 kHz                Upper-mid, guitars
  25-29     2-4 kHz                Presence, cymbals
  30-34     4-6 kHz                High, hi-hats
  35-39     6-10 kHz               Air, brilliance

Helper Functions:
  getBass()       → Average of bands 0-9  (bass & sub-bass)
  getMid()        → Average of bands 10-19 (vocals & mid)
  getTreble()     → Average of bands 20-29 (presence)
  getHighTreble() → Average of bands 30-39 (air)

================================================================================
                        COMPARISON: BEFORE vs AFTER
================================================================================

BEFORE (Multiple analogRead() calls):
────────────────────────────────────────────────────────

Frame Loop:
  AudioReactive::update()  → analogRead(A0)   ─┐
  VUMeter::update()        → analogRead(A0)   ─┼─ 3 slow analog reads
  CustomAudio::update()    → analogRead(A0)   ─┘
  
Problems:
  ✗ Each analogRead() takes ~50µs (slow)
  ✗ Noisy data (no FFT, just amplitude)
  ✗ Inconsistent between functions
  ✗ No frequency information
  ✗ High CPU usage for multiple reads
  ✗ Timing issues (reads at different times)

AFTER (Centralized AudioSystem with FFT):
────────────────────────────────────────────────────────

Frame Loop:
  AudioSystem::update()    → FFT1024 (once)   ─┐
  AudioReactive::update()  → cached[...]       ├─ 1 FFT, instant cache access
  VUMeter::update()        → cached[...]       │
  CustomAudio::update()    → cached[...]      ─┘

Benefits:
  ✓ Single FFT calculation (efficient)
  ✓ Clean frequency data (40 bands)
  ✓ Consistent data across all functions
  ✓ Rich frequency information
  ✓ Lower CPU usage overall
  ✓ Perfect synchronization
  ✓ Instant cache access (no wait)
  ✓ Peak detection included
  ✓ Band averaging helpers
  ✓ Adjustable gain/sensitivity
