HDLO Controller

This code manages the lights for a display of the edges of the 24-cell, stereographically projected vertex-down into a gallery space. 

The top-level work-flow is:

=============================

0) The physical lights: The pin info is kept in led_constants.h, as well as 

stranddata[numberofpins][maxedgesperstrand][3] = 
{
  {//strand #0
    {#leds on segment 0 ,edge #, #direction}, 
    {36,4,-1},
    {36,11,1}},
....
}

From this, we create strandtable in the initialization, that maps each individual LED
to a position along on an edge in the 24 cell. During the loop, these positions are fed into:


=============================

1) Color Functions

Color functions are registered in colorfunctions.h and cpp, and can be defined in any way -- their only responsibility is to return an CRGB given a position value x from 0 to 1.

By the time a color function is called, time may already be factored into x (adding time, or sine of time, etc); color functions are free to make use of time themselves, as well as any other information they can pull from: sound, touch sensors, etc. 


Lots to explore!


============================

2) Color Models

A color model is an assignment of colors 1,2,3,... (and their directions) to the edges of the 24-cell. (The actual colorfunctions are paired with the indices of the colors in the specification of a color sequence.)

The files hdlo_models.h and cpp are generated by the hdlo viewer js program, automatically printing out all models in ourModelRegistry defined there. 

It would be pretty straightforward to bring over generating symmetries of the 24-cell, encoded as an array of indices, edge[index]-> edge[perm[index]], and have code to compose permutations. 

Similarly, we can easily merge models -- if one has entries are 0, use the other. 

In this way, we can do more of the assembly in this code, importing less -- TBD


The actual mapping is handled in edgesetup.h which constructs  strandtable[i] mapping the ith led in the one long rgbarray  to a position x in an edge colored by some colorfunction. Additional timing, scaling, shifting info is factored in at the moment that the colorfunction is applied. 


=============================

3) Color Sequences

The color sequences are created in one single script in sequences.cpp

Each color sequence looks like this:


seq->startNewSequence("Name", duration_ms, enabled);
seq->addStepByName(modelNames[idx], {"colors"}, duration, TYPE, trans_dur);
etc.

// for example:

  // Sequence 0: Default Flow - 4500 seconds
  seq->startNewSequence("Default Flow", 4500, true);
  seq->addStepByName("flowoctahedron", {"dark", "rainbow", "bluetored", "staticblue"}, 100, FADE, 1);
  seq->addStepByName("flowoctahedroncompound1", {"dark", "bluetored", "rainbow", "staticblue"}, 100, WIPE, 1.5);
